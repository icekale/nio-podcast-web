# 车机端设计理念对照分析与分类改造方案

> 基于 2026-08-09 车机端 NIO Radio 截图（4 张）与 PC 端（nio.k4le.top）现状分析。

## 一、车机端设计理念拆解

### 1.1 信息架构（点播页从上到下）

```
Tab: 推荐 | 点播
──────────────
[我喜欢] [最近播放]        ← 两个高频个人入口卡片
──────────────
通勤场景 | 资讯速递  >      ← 分类标题（场景 | 子类）+ 进入更多
[卡片][卡片][卡片]...       ← 横向滚动封面卡队列
──────────────
宝贝同行 | 哄娃陪伴  >
[卡片][卡片][卡片]...
──────────────
舒缓驾驶 | 乐伴旅途  >
[卡片][卡片][卡片]...
──────────────
迷你播放器（固定底部）
```

### 1.2 核心设计理念

| 理念 | 车机端做法 | 本质 |
|---|---|---|
| 场景化分类 | 分类按"驾驶场景"命名：通勤/哄娃/舒缓驾驶/长途/城市漫游/玩转爱车 | 用**使用场景**而非**内容类型**组织节目，降低找内容成本 |
| 分区横向流 | 每类只露一行卡片，横向滑动 | 避免 500+ 专辑混在一个长列表里，老专辑不被埋没 |
| 高频入口置顶 | 我喜欢/最近播放 两个大卡片 | 个人化入口优先于内容浏览 |
| 封面为主 | 方形封面 + 标题 + 右下播放角标 | 视觉识别优先于文字 |
| 播放器常驻 | 底部迷你播放器，浏览不中断 | 与 PC 端 MiniPlayer 一致 |

## 二、PC 端对照：哪些可借鉴、哪些不可

### 2.1 现状盘点（PC 端已有）

- 今日推荐面板 + 今日更新/最新更新列表（首页）
- 全部专辑（列表/桌面 grid）、搜索、稍后播放、我的收藏
- MiniPlayer 常驻、桌面侧边导航
- 排序：最新时间优先 + BOOSTED 权重（35 芝士分子、584 N问）

### 2.2 差距分析

| 能力 | 车机端 | PC 端 | 结论 |
|---|---|---|---|
| 场景分类组织 | 6 个场景分区 | ❌ 无，全部专辑一个长列表 | **核心差距**，用户痛点（老专辑被埋没） |
| 个人高频入口 | 我喜欢/最近播放 置顶 | 部分（收藏页在导航） | 可借鉴：专辑页顶部放收藏/最近入口 |
| 横向卡片流 | 每类一行卡片 | 桌面 grid（无分组） | 可借鉴：分区 + 横向滑动 |
| 播放按钮浮在封面 | 右下角播放角标 | 点击进专辑页 | 车机是"直接播"；PC 端点封面进专辑是合理差异，**不照搬** |
| 底部播放器 | 常驻 | ✅ 已有 MiniPlayer | 已一致 |

### 2.3 设计边界（PRODUCT.md 约束）

PRODUCT.md 明确：*"Do not resemble a vehicle dashboard or large-format in-car interface"*——即**不照搬车机视觉**（大圆角卡片、低信息密度、横向大流），但**借鉴信息架构**（场景分类、分区组织）不冲突。本方案只借鉴架构，不改变视觉风格。

## 三、分类改造方案

### 3.1 数据源决策：官方 API 无分类接口

已实测（2026-08-09）：`v2/album/category`、`v2/category/list`、`v2/audio/category` 等十几个候选接口全部 404；`v2/album/list` 返回 643 个专辑但**无分类字段**。车机端分类是官方运营私有数据，公开接口拿不到。

**结论：自建分类映射**（人工维护专辑 ID → 场景分类，与现有 catalog 抓取模式一致）。

### 3.2 数据流

```
scripts/album-categories.js  ← 新增：映射表 + 关键词规则
        │
scripts/catalog-generator.js ← 生成目录时打 category 字段
        │
public/data/albums.json      ← 每个专辑多一个 "category": "通勤场景|资讯速递"
        │
src/catalog.js               ← 新增 groupAlbumsByCategory() 选择器
        │
AlbumsScreen                 ← 改为分类分区视图（保留"全部专辑"兜底）
```

### 3.3 分类映射策略（三级兜底）

1. **人工 ID 映射**（最高优先，§1.3 已确认 26 个 ID）
2. **名称关键词规则**（自动兜底，如：`城市频道|城市资讯|天气预报` → 城市漫游；`故事|绘本|童|少年|亲子` → 宝贝同行；`音乐|乐行|精选集` 等 → 按子类）
3. **未命中 → "更多专辑"兜底分区**（不丢弃任何专辑）

### 3.4 前端 UI 方案

**AlbumsScreen 重构为分类分区页**（改动最小、直击痛点）：

```
全部专辑（标题 + 计数）
─────────────────────
通勤场景 | 资讯速递        →
[封面卡][封面卡][封面卡]...   ← 横向滚动一行（移动端）/ 自适应 grid（桌面）
─────────────────────
宝贝同行 | 哄娃陪伴        →
[封面卡][封面卡][封面卡]...
─────────────────────
...（6 个场景分区，按分区内最新时间排序）
─────────────────────
更多专辑                  → 未分类兜底（现有列表/加载更多）
```

- 分类标题行：`场景 | 子类` + `>` 箭头，点击进入该分类全量 grid（复用现有 `sortAlbumsForDirectory`）
- 分区内排序：`BOOSTED_ALBUM_IDS` 权重 → 最新时间 → ID（上一轮机制保留）
- 每个分区露出约 8-10 张卡片 + 横向滚动（移动端）/ grid（桌面）
- 专辑卡复用现有 `AlbumResults`（grid 模式），仅增加横向滚动容器
- 保留"全部专辑"完整列表入口（现有 `#/albums` 路由作为兜底视图，避免信息丢失）

### 3.5 不做的事（YAGNI）

- ❌ 不做"推荐/点播"双 Tab 大改版——首页今日推荐已有同等功能
- ❌ 不做封面播放角标直接播放——与现有"点封面进专辑"交互冲突
- ❌ 不做"最近播放"入口——桌面导航已有稍后播放/收藏，且播放历史是设备本地数据，价值低
- ❌ 不把分类做进首页——首页以"今日更新"为核心定位，分类放专辑页即可

## 四、实施步骤

| 步骤 | 内容 | 验证 |
|---|---|---|
| 1 | 新增 `scripts/album-categories.js`（26 个确认 ID + 关键词规则） | 单测：规则命中、兜底不丢 |
| 2 | `catalog-generator.js` 生成时合并 `category` 字段 | 单测：生成目录含分类；重新生成目录并部署 |
| 3 | `src/catalog.js` 新增 `groupAlbumsByCategory()` | 单测：分区顺序、未分类兜底 |
| 4 | `AlbumsScreen` 分区视图 + CSS（横向滚动行/桌面 grid） | 组件测试 + 手动验证 |
| 5 | 提交 → CI（测试+lint+build）→ 部署 → 线上验证 | 线上检查分类可见 |

## 五、风险与备注

- 分类映射是**快照**：新专辑（如新城市频道）需靠关键词规则兜底，人工映射定期补充即可
- 车机端分类名若后续变化，改 `album-categories.js` 一处即可，前端无感
- 截图中有 `"马"上开聊`(800)、`2026新春祝福`(799) 等较新专辑，映射已含
