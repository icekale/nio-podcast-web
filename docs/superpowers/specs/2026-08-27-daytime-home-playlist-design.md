# NIO Radio 日间首页播放列表设计

**日期：** 2026-08-27

**目标：** 将 Web/PWA 首页的播放列表数据源切换为 NIO Radio 官方动态「日间」列表，并保留现有目录作为失败回退。

## 设计

新增 `src/api.js` 的日间列表请求，调用：

`https://gateway-front-external.nio.com/moat/100914/v2/radio/list`

请求成功后将响应数组映射为现有播放器使用的 episode 结构，至少保留 `audioId`、`audioName`、`albumId`、`albumName`、封面、时长、发布时间和可播放音频地址。映射结果按官方返回顺序排列，不按目录排序或去重。`dcvId.date` 作为响应的日期元数据返回，`dcvId.schemeId` 和 `clockId` 仅作为原始更新标识保留在结果元数据中，不固定任何 scheme ID。

`App` 在非测试的运行时首页生命周期中请求日间列表，并与现有目录刷新保持相同的 5 分钟前台刷新节奏。请求去重和 10 分钟成功缓存放在 API 层；失败请求不缓存。最新一次成功的非空日间结果作为首页播放列表，传给 `HomeScreen`。`HomeScreen` 只在收到非空日间列表时覆盖 `selectHomeEpisodes` 的目录结果，并将播放列表标题显示为「日间」；目录回退时继续使用原有标题。因此首页现有的播放、全部播放和播放器队列逻辑继续复用，只调整这一处标题文案。

如果日间请求失败、响应格式无效或结果为空，`App` 将日间状态置为不可用，`HomeScreen` 继续使用当前目录选择结果。日间失败不显示新的错误提示，避免改变现有界面；目录本身的错误和缓存提示保持原状。日间请求不会修改目录缓存、搜索数据、专辑详情或专辑目录排序。

## 测试

先在 `src/api.test.js` 增加日间响应字段映射、`dcvId` 日期/标识提取、空/错误响应和缓存去重测试；再在首页测试中验证成功日间列表用于单条播放和全部播放，失败时仍使用目录列表。运行目标测试确认新增测试在实现前失败，再实现 API 和首页数据传递。

## 范围

只修改首页播放列表的数据流、日间生效时的列表标题及其 API/测试覆盖。不要修改视觉、布局、现有播放控制、播放器状态模型、专辑目录生成、搜索、专辑详情或小程序项目。
